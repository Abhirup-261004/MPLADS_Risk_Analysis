# Feature 3 Context: NLP-Driven Categorization

## What We Did
We implemented a comprehensive NLP pipeline to automatically categorize MPLADS projects based on their free-text descriptions. Since over 97% of the raw dataset was unhelpfully tagged as "Normal/Others", we used AI to extract the true physical asset types.
- **Embeddings:** Cleaned code-mixed (Hindi/English) text and embedded it using a multilingual `SentenceTransformer` (`paraphrase-multilingual-MiniLM-L12-v2`).
- **Clustering:** Reduced dimensions with UMAP and clustered with HDBSCAN to find natural groupings without requiring manually labeled data upfront.
- **Labeling & Classification:** Mapped clusters to 11 official MPLADS categories using a hybrid semantic-keyword approach. We then trained a TF-IDF + LightGBM classifier (97.7% validation accuracy) to instantly categorize any future incoming data.
- **Mismatch Detection:** Flagged projects where the NLP category confidently contradicted the officially declared category (e.g., claiming to build a hospital but the text describes a road).

## What It Produces
Feature 3 exports its artifacts cleanly, respecting the separation between canonical data and model internals:
1. **`shared_preprocessing_artifacts/fact_work_feature3.parquet`**: This is the most critical output. It is the enriched canonical fact table containing new columns like `category_nlp`, `category_nlp_confidence`, and `category_mismatch_flag`.
2. **`feature3_artifacts/`**: Stores internal ML objects (`.joblib` files, the sentence transformer model weights, UMAP/HDBSCAN models), EDA plots, and configuration JSONs (`feature3_taxonomy_config.json`). *Note: These are heavy ML files kept intentionally isolated from Git tracking and the shared data bus.*

## How It Will Be Used for Next Features
Feature 3 acts as a **foundational prerequisite** for downstream anomaly detection.
- **Feature 1 (Disbursement Risk) & Feature 2 (Cost Benchmarking):** Both features rely heavily on "peer grouping". To detect if a project is too expensive (Feature 2) or under-disbursed (Feature 1), the models must compare it to similar projects. Feature 3 provides `category_nlp`, allowing downstream features to accurately group "Roads" with "Roads" and "Hospitals" with "Hospitals" within the same state.
- **Feature 4 (Duplicate Work & Structuring Detection):** Feature 4 will search for identical works split to bypass funding thresholds. It will directly reuse the dense text embeddings generated by Feature 3's `SentenceTransformer` to calculate cosine similarity between projects, saving massive compute overhead.

**Next Step Handoff:**
When building Feature 2 or Feature 4, the architecture dictates ingesting `shared_preprocessing_artifacts/fact_work_feature3.parquet` as the primary dataset instead of the raw `fact_work`.
